**001, ce que le relevé a de faux ou de périmé** (lu sur 0.12.2) : 10 339 lignes de JavaScript (pas 8 800), sans bibliothèque. Le moteur n'appelle plus que son `port` (`js/grist.js` est l'`http` de Sync+ et la lecture des tables). Il écrit aussi `RecalculLe` (avec `id_sync` et `MajLe`) et les colonnes `Sync_*` des journaux. Tables `_grist_*` lues ou écrites : `_grist_Tables`, `_grist_Tables_column`, `_grist_Views`, `_grist_Views_section`, `_grist_Views_section_field`, `_grist_Pages`, `_grist_Shares`, `_grist_ACLResources`, `_grist_ACLRules`, `_grist_Attachments`, `_grist_Triggers` (conditions des webhooks, dans `rest-port.js`). Limites à ajouter : un envoi Grist fait 1 Mo au plus (lots de 250 ko, en tranches), file de 1 000 événements par document, renvois sous un budget de 20 Mo par 10 minutes.

**002, ce qui est fait :** dossier `js/engine/` (mode d'emploi : `js/engine/README.md`). Démarrage `startEngine({ port, prefix, version })`. Préfixe : défaut `''` (les noms d'aujourd'hui), forme `[A-Z][A-Za-z0-9_]{0,31}` ; avec `Gfs_` : `Gfs_Synchro`, `Gfs_Journal_<export>`, destinations `Gfs_<nom>` ; les colonnes (`Synchro_Export`, `id_sync`, `MajLe`…) ne changent pas. Port : `PORT_SHAPE` (`js/engine/port.js`, refusé s'il est incomplet). **Accès à l'écran dans le moteur : aucun** (`document`, `window`, `location`, `navigator`, `localStorage`, `grist` refusés par `tests/unit/engine.test.mjs`, qui vérifie aussi que le moteur n'importe aucun écran).

**005 · le jugement d'un lien collé, dans le moteur.** `PORT_SHAPE` (groupes `data` et `publicDoc`) exige `shareInfo(adresse)` (la fiche du document que désigne la clé : `null` si la clé est inconnue, `shareUnreadable` si Grist ne répond pas ou si l'adresse n'est pas de cette instance), `publicAccess(base)` (`'viewers'`, `'editors'`, `''` fermé, `null` muet) et `journalStats(table, colonneRecu, colonneType)` (`{ n, last, raw }`, `null` si Grist refuse) ; `setPort` refuse un port qui ne les a pas ; moteur **2.0.0**, toutes trois dans `createRestPort`. **Aucun contrôle de lien dans un écran** : le moteur refuse un lien d'un autre document (`shareOtherDoc`), une clé coupée (`shareUnknown`), un Grist muet (`shareUnreadable`), un lien qui n'écrit pas dans le journal (`linkTest`, `linkElsewhere`), une autre instance (`otherInstance`), une invitation périmée (`invitationExpired` ; `invitationState(inv)` → `'link'`, `'expired'`, `'valid'`), une signature fausse, une clé publique remplacée (le code de contrôle change). La comparaison du code de contrôle en sécurité renforcée était une règle d'écran : elle est maintenant dans le moteur, `approveReply(exp, inv, reply, { compared })` ; Échange renforcé côté CIBLE : `checkDestinations(invitation, plans, { compared })` et `createReception(…, { compared })` (`mustCompare(invitation)` dit s'il faut la demander) ; sans `compared`, `codeNotCompared` avant toute écriture. Essais sur le Grist en mémoire (`tests/unit/engine-links.test.mjs`, 9) : lien d'un autre document refusé (CIBLE et SOURCE), clé inconnue, Grist muet (réponse et invitation d'Échange), clé publique remplacée, code non comparé (SOURCE et CIBLE, rien d'écrit), invitation périmée et d'une autre instance, `PORT_SHAPE` refuse un port sans les trois fonctions.

## Changements qui touchent GFS
- 2026-11-09 · `edb0988` · **moteur 2.3.0, mineure** (Sync+ 0.14.0, demande du porteur de Sync+ : « prévoir une sync dans les deux sens pour les pj également », choix « complet, dans la Bêta ») : dans un Échange, les pièces jointes vont aussi du participant vers l'export qui invite. `exchangeTables` (`logic/exports.js`) garde les colonnes Pièces jointes dans l'export de retour ; `fileSends` (`logic/files.js`) n'envoie pas à un webhook un fichier qu'il a lui-même cité (champ `o` du suivi `fichiers`, rempli par `noteHeldFiles`, `source/files.js`, à partir des seules versions déjà vérifiées par signature et sceau) ; `planConsolidation` reçoit `waiting` (`waitingVersions`) : en Échange, une version dont un fichier n'est pas encore arrivé n'est pas recopiée et reste dans le journal (`plan.waiting`, gardée par la purge) ; la carte de réception dit « N lignes attendent leurs fichiers » (`filesSummary` rend `held`). Port, noms de table, format des codes (`CODE_FORMAT`) inchangés ; rien à écrire côté hôte, sauf montrer `held` sur la carte si l'hôte montre déjà `files`. Les deux documents d'un Échange doivent avoir cette version (un participant plus ancien écrirait des cellules incomplètes) : sans effet tant que Sync+ n'est pas publié.
